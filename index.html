Self-Hosted PaaS with a Resilient Distributed Scheduler

PythonFastAPIPostgreSQLKubernetesKanikoTerraformDockerPrometheusGrafanaOpenTelemetryGitHub Actions

Heroku-style platform where a git push produces a live URL, powered by a distributed job scheduler written from scratch instead of Celery. The scheduler uses Raft leader election (with pre-vote and check-quorum) and Postgres fencing epochs to prevent split-brain, along with heartbeat leases, exponential-backoff retries, a dead-letter queue with compensation jobs, idempotent enqueue, and exactly-once side effects. Each deploy runs as a chained build → deploy → verify pipeline: images are built with Kaniko and the release is rolled back automatically on failure. The pipeline runs end to end locally, and a Kubernetes runtime that server-side-applies Deployments is written and validated for kind, EKS, and GKE. The FastAPI control plane and a Typer CLI handle releases, rollbacks, config, scaling, and logs. A custom chaos harness kills, freezes, and network-partitions the leader and workers under load, then checks invariants against the database. In a 180-second fault run at 25 jobs/s across 3 scheduler nodes and 3 workers, it lost 0 of 4,652 acknowledged jobs, recorded 0 exactly-once violations, kept 100% control-plane availability, and failed the leader over in about 1 second. The harness also found a real failover bug, which was fixed and covered by a regression test. The project also includes Terraform modules for AWS EKS and GCP GKE (passing terraform validate), Prometheus/Grafana dashboards with alert rules, end-to-end OpenTelemetry tracing, and a CI chaos gate in GitHub Actions.
